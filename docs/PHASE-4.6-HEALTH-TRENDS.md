# HaniLog — Phase 4.6 Health Trends & Glucose Visualization

**상태:** 구현 및 로컬 코드 검증 완료. 실제 모바일 브라우저, 로컬 PostgreSQL/RLS, GitHub Actions 시각 검증은 미완료.

## 1. 그래프 정보 구조

- 신규 `/trends` 화면을 추가하고 기간 선택을 `7일 / 30일 / 90일 / 1년 / 전체`로 제공합니다. 기간은 현재 시각 기준 rolling window이며 검사 빈도를 권고하지 않습니다.
- 날짜별 점은 `occurred_at`의 실제 UTC instant를 X 좌표로 사용합니다. 측정 사이를 선으로 잇지 않고 보간값도 만들지 않습니다. 따라서 장기 불규칙 측정의 빈 구간이 연속 관측처럼 보이지 않습니다.
- 점을 탭하거나 키보드로 포커스하면 측정값, 실제 측정 시각, 서버 입력 시각, 측정자, 기록자, 선택적 출처·조건·메모와 정정 여부를 표시합니다. 목록도 제공하므로 정보는 그래프에만 의존하지 않습니다.
- 같은 날 여러 측정과 같은 시각의 별도 이벤트를 보존합니다. 선택한 날짜의 식사·인슐린 기록은 실제 시각, 수행자, 기록자와 함께 별도 목록으로 보여주며 인과관계나 예상 혈당 변화는 표현하지 않습니다.
- 최신값과 직전값의 숫자 차이만 표기합니다. 개선·악화나 치료효과로 해석하지 않습니다. 1년·전체 구간에서는 저장된 측정 건수만 월별로 집계하며 평균·중앙값은 계산하지 않습니다.
- 긴 측정 공백은 기간별 간격 안내로 표시하고 기록 부재를 미실시나 정상으로 해석하지 않습니다.

## 2. 측정값과 검사 출처 데이터 모델

- 기존 `health_events`의 `event_type='glucose'`, `occurred_at`, `recorded_at`, `actor_id`, `performer_id`, `value`, `unit`, `occurrence_id`를 재사용했습니다. 별도 혈당 테이블이나 복제 데이터를 만들지 않았습니다.
- 신규 Quick Record 입력의 선택 측정 출처와 측정 조건은 기존 `value` JSONB 안의 `measurement_source`, `measurement_condition`에 넣습니다. 예: 식사 전/후/식사와 무관. 이는 설명 metadata일 뿐 Safety Guard의 임상 규칙으로 사용하지 않습니다.
- 기존 DB `source`는 `USER_ENTERED`/`IMPORTED`인 이벤트 입력 경로이므로 측정기·검사기관과 혼동하지 않습니다. 출처가 비어 있으면 `미기록`으로 표시합니다.
- 기존 정정 구조를 유지합니다. 화면은 이벤트 원본을 수정하지 않고 최신 revision patch의 값·단위를 적용하며, 최신 `VOID`는 추세에서 제외합니다. 원본과 revision 행은 그대로 둡니다.
- 새 DB 필드·테이블이 없어 이번 Phase에서는 추가 migration을 만들지 않았습니다. 기존 mg/dL insert 계약은 유지됩니다.
- 혈액검사 장기 추적 모델은 이번 범위에 포함하지 않았습니다. 검사 항목, 검사법, 기관, 원래 단위, 참고범위 출처를 별도 결과 엔터티로 설계해야 하며 서로 다른 검사항목을 Health Event 혈당 시계열에 혼합하지 않는 후속 설계가 필요합니다. 자동 해석·진단은 범위 밖입니다.

## 3. 차트 라이브러리

- 외부 차트 라이브러리를 추가하지 않고 반응형 SVG 산점도를 구현했습니다. 번들 의존성·용량을 늘리지 않고 실제 timestamp 좌표, 포커스 가능한 측정점, 모바일 탭 상세를 직접 통제할 수 있습니다.
- 접근성 이름과 키보드 선택을 제공하고 아래에 동일 데이터의 목록을 함께 둡니다. 기본 프로덕션 JS bundle은 349.06 kB (gzip 107.39 kB)였습니다. 이 수치는 기존 앱 전체 번들이며 그래프 단독 크기가 아닙니다.
- 유지보수상 차트의 축·선택 동작을 자체 관리해야 합니다. 향후 줌·팬 등 고급 기능이 필요하면 접근성·번들 비용을 다시 비교합니다.

## 4. 모바일 UI 및 Dashboard

- 모바일 우선 단일 열, 좁은 패널 여백, 44px 기간 버튼, 가로 넘침 방지 스타일을 추가했습니다. 태블릿 이상에서는 그래프와 기록 목록을 나누고 데스크톱에서는 넓은 차트·상세 패널 구조로 배치합니다.
- 다섯 기간 선택, 최신/직전 숫자 비교, 측정 상세, 기록 목록, 빈 상태, 오래된 단위 제외 안내를 구현했습니다.
- Dashboard의 최근 혈당 카드에는 mg/dL로 호환되는 최근 기록과 최대 8개의 점 미리보기를 추가했습니다. 전체 그래프는 상세 화면으로 연결합니다.
- Quick Record는 mg/dL을 고정 표시하고 숫자 키패드, 선택 측정 출처·조건 입력을 제공합니다. 혈당 단위 선택 UI는 없습니다.
- 하단 내비게이션에 “건강 추세”를 추가하고 7개 항목 그리드로 변경했습니다. 데스크톱 사이드 내비게이션 동작은 기존 breakpoint를 따릅니다.
- DEMO는 90일 합성 혈당 예시 및 당일 복수 측정 예시를 보여줍니다. 값은 전적으로 화면 확인용이며 저장되지 않고 임상 임계값·권고는 없습니다.

## 5. 데이터 누락, 정렬 및 단위

- 서버 모드는 선택 Pet의 RLS 적용 `health_events`를 1,000행 페이지로 읽고, 해당 ID의 revision을 500개씩 조회합니다. 정렬은 `occurred_at ASC`, 동시각 tie-break는 ID 순서입니다.
- Pet 시간대(IANA)를 사용해 표시와 월별 횟수 경계를 계산하며 실제 시각·기록 시각은 구분합니다. 날짜 경계는 표시 단계에서 현지 시간대로 변환하고 원 UTC instant는 바꾸지 않습니다.
- 그래프 포함 조건은 유효 숫자와 정확한 `mg/dL` 단위입니다. 다른 단위·단위 미기록 값은 원본을 변환·재라벨하지 않고 별도 접기 영역에 제외 사유와 저장 단위를 보여줍니다. 그래프·요약·목록은 호환되는 mg/dL 기록만 대상으로 합니다.
- 값이 없는 날짜에 점을 생성하지 않습니다. 일별·격주·월간·3개월 이상 공백은 시간축상의 간격과 안내로 남깁니다.
- 서버 조회 실패나 오프라인에서는 과거 결과를 최신 데이터처럼 보이지 않고 `UNVERIFIED`만 표시합니다. 서버 최신 상태를 확인하지 못하면 기록 그래프를 렌더하지 않습니다.

## 9. 남은 범위와 위험

1. 375px·태블릿·데스크톱의 실제 브라우저 레이아웃과 VoiceOver/TalkBack/키보드 시각 동작 미검증.

3. GitHub Actions 실제 run 미실행.
4. 측정 출처·조건은 현재 JSONB metadata라 DB 수준 enum/check 제약이 없습니다. 임상 의미의 확대가 필요하면 변경 정책과 호환성을 따로 설계해야 합니다.
5. 과거 revision patch가 다양한 형식으로 저장된 실제 데이터가 없어서 현재 구현이 `patch.observed_value`, `patch.value.observed_value`, `patch.unit` 형식을 지원하도록 했으나 실제 저장 이력 전체에 대한 검증은 남았습니다.
6. 혈액검사 장기 추적·검사법별 비교 모델은 후속 단계에서 별도 검토해야 합니다.
